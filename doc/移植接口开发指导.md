# 移植接口开发指导

### 基本架构

一个标准的移植接口模块的目录架构如下：

```
项目根路径/
|--include/
|----模块名/
|------trait（可选）/
|------具体实现A/
|------具体实现B/
|------..../
```

``include``目录的每一个子目录对应一个移植接口模块。模块下的``trait``目录通常用于约束具体实现的接口，未达到接口要求的实现会在编译期由``static_assert``自动触发。动态接入的接口模块（例如``HeapAllocator``等分配器）通常使用虚函数实现多态效果，这类模块通常不具有``trait``。

特别的：
* ``include/Basic``下存放着其本身不需要任何移植就能使用的库，这些库通常提供了一些基本定义（例如用于表示大小的整型数据类型``Size``）。
* 项目主体通过调用移植接口来实现更复杂的功能，但移植接口不应该调用项目主体。即项目主体只能单向调用移植接口。
* 有关移植接口的全局默认配置通常被存放在``config``目录下，例如默认的分配器。

以经典的``ArrayList``模块为例。其代码位于``include/ArrayList``目录，接口约束位于``include/ArrayList/trait``目录（即``include/ArrayList/trait/ArrayListTrait.hpp``），而诸如``include/ArrayList/stdcpp``则是基于标准C++的接口实现。

### 在代码中导入移植接口模块

根据模块的文档等相关引导，直接使用C++的``#include``语法即可。

例如，导入模块``ArrayList``只需要以下代码：

```C++
#include "ArrayList.hpp"
```

其中，``ArrayList.hpp``由模块开发者提供，作为该模块的入口文件。

一个模块可能会有若干个入口文件，具体情况因不同模块而异。

值得注意的是：
* 通常情况下，被导入的文件不应该是接口约束文件。例如应导入``ArrayList.hpp``而非``ArrayListTrait.hpp``。
* 通常情况下，请导入入口文件的文件名，而不是具体的绝对路径或相对路径，文件名所在路径应该在编译时指定。例如应导入``ArrayList.hpp``而非``D:/stamon2/include/ArrayList/stdc/ArrayList.hpp``

### 在构建系统中导入移植接口模块

Stamon采用**一体化编译**的方式来编译项目。因此可直接添加目标模块的``trait``目录（如果有的话），并选择合适的对应实现作为编译器的头文件搜索路径。

例如，在``g++``编译器中，使用``-I <dir>``即可将``<dir>``添加至头文件搜索路径中。若要导入``ArrayList``的``stdcpp``实现，则可添加以下参数：

```Makefile
-I include/ArrayList/trait -I include/ArrayList/stdcpp
```

此时的工作目录应该是项目根目录。

### 开发一个移植接口模块

开发者在移植过程中，可以为必要的移植接口模块选择并接入最佳的具体实现，也可以自己动手实现。

我们欢迎更多开发者为不同平台贡献移植实现。

接下来，笔者将带领大家从头开发一个``Example``模块（这个模块将提供一个``sayHelloWorld``方法），并把它接入到项目中。

笔者在``Alpine Linux v3.23 x86_64``的系统环境下进行开发，编译器版本为``gcc version 15.2.0 (Alpine 15.2.0)``。

##### 创建对应目录和文件

在Stamon源码的基础上创建如下的目录和文件结构：

```
项目根路径/
|--include/
|----Example/
|------trait/
|--------ExampleTrait.hpp
|------stdcpp/
|--------Example.hpp
|--test/
|------Example/
|--------Test.cpp
```

如果你正在使用现代IDE开发，笔者建议在compile_flags.txt的末尾加入：

```text
-Iinclude/Example/trait
-Iinclude/Example/stdcpp
```

这能让IDE找到对应的文件，让读者获得更好的编码体验。

##### 编写接口约束

``ExampleTrait.hpp``的代码如下所示：

```C++
#pragma once

#include "StamonLib.hpp"

namespace stamon::trait {

template<typename C> concept ExampleTrait = requires(const C &obj_const) {
	C(); // 可默认构造
	requires Copyable<C>; // 可拷贝构造
	requires Movable<C>; // 可移动构造
	{ obj_const.sayHelloWorld() }->SameAs<void>; // 可以输出"Hello world!"
};

template<typename C> using checkExampleTrait = checkTrait<C, ExampleTrait<C>>;
// 按照惯例，我们通常设置一个checkExampleTrait<C>，如果静态断言没有报错，则返回C本身
// checkTrait会对第二个模板参数进行静态断言，如果没有报错则返回第一个模板类型

} // namespace stamon::trait
```

##### 编写对应实现

``Example.hpp``的代码如下所示：

```C++
#pragma once

#include "ExampleTrait.hpp"
#include <iostream>

namespace stamon::stdcpp {
// 具体实现通常不直接编写到namespace stamon中
class Example {
public:
	void sayHelloWorld() const {
		std::cout << "Hello world!" << std::endl;
	}
};
} // namespace stamon::stdcpp

namespace stamon {
using Example = trait::checkExampleTrait<stdcpp::Example>;
//通过checkExampleTrait实现接口检查
} // namespace stamon
```

值得注意的是，在对模板类进行约束时，我们也能采用这套方式。以``ArrayList``为例，假设``ArrayList``的接口约束工具是``checkArrayListTrait<C, T>``，其中``C``是``ArrayList<T>``，``T``是模板类型。

我们可以使用如下方法，对所有被实例化的ArrayList进行检查：

```C++
template<typename T>
using ArrayList = trait::checkArrayListTrait<stdcpp::ArrayList<T>, T>;
```

##### 编写示例项目的入口代码

``Test.cpp``的代码如下所示：

```C++
#include"Example.hpp"

int main() {
    stamon::Example example;
    example.sayHelloWorld();
    return 0;
}
```

##### 构建示例项目

使用如下指令编译示例项目：

```
g++ test/Example/Test.cpp \
-o bin/stamon_test \
-O2 -std=c++20 \
-static \
-I include/Basic -I include/Example/trait -I include/Example/stdcpp
```

生成的可执行文件为``bin/stamon_test``

``-O2 -std=c++20- -static``用于优化项目、指定代码标准、生成静态的可执行文件。

通常情况下，任何项目都应该包含``include/Basic``，``Basic``目录中存放着整个项目所依赖的，平台无关的基础代码。

除此之外开发者还要记得把自己开发的模块的接口约束目录和对应实现目录都添加进来。

##### 运行示例项目

运行``./bin/stamon_test``即可得到输出。至此，我们成功开发了一个简单的模块。

```
root in /mnt/d/stamon2.5 > ./bin/stamon_test
Hello world!

root in /mnt/d/stamon2.5 >
```

##### 注意事项

* 接口约束代码只应导入必要的模块，并且除调用其他模块以外，本身不应该出现其他平台相关代码，否则会降低可移植性
